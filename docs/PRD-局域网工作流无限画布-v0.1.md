# 局域网工作流无限画布 PRD

版本：v0.1  
日期：2026-10-11  
状态：第一版核心需求已确认；未确定的细节见“假设与待确认问题”。

## 1. 摘要

开发一个在局域网内通过浏览器使用的无限画布，供产品发起人及朋友进行图片生成和编辑。用户把文字、图片和封装好的工作流节点手动连线，即可连续完成“文字生成图片 → 选图 → 图片编辑”。工作流由发起人统一准备，执行来源包括其电脑上的 ComfyUI 和 RunningHub。

## 2. 背景

当前使用流程存在四个问题：反复下载和上传图片、在不同页面间切换、难以找回历史版本、难以比较多张结果。

朋友不懂 ComfyUI 工作流，需要通过清楚的节点名称和有限的参数完成操作。由发起人准备工作流、模型及运行环境，朋友使用封装后的节点。第一版重点是让完整图片处理流程在同一画布内完成。

## 3. 目标与成功指标

目标：减少图片流转操作，保留创作过程，并让多人共用执行资源时互不干扰。

| 验收目标 | 第一版完成标准 | 验证方式 |
|---|---|---|
| 新用户能完成流程 | 至少一位不懂 ComfyUI 的朋友，经过简单说明后，独立注册、生成或上传图片、选图并编辑；全过程无需手动下载后再上传 | 实际观察一次完整使用过程 |
| 多人互不干扰 | 至少两个账号使用同一工作流时，参数、画布和历史记录独立；原始工作流保持不变 | 两个账号提交不同参数的任务，检查任务与结果归属 |
| 内容可以恢复 | 关闭页面再登录，画布、连线、参数、历史图片及选中的版本全部恢复 | 保存包含多版本图片的画布，关闭后重新登录检查 |

以上三个标准已由产品发起人确认。

## 4. 目标用户

| 用户 | 主要任务 | 需求与约束 |
|---|---|---|
| 产品发起人兼工作流维护者 | 准备和更新工作流，设置可开放参数，使用画布创作 | 统一维护本地 ComfyUI 和 RunningHub 连接，保持工作流模板稳定 |
| 不懂 ComfyUI 的朋友 | 通过文字或已有图片进行生成、编辑、比较和继续修改 | 通过浏览器使用现成节点；自行注册账号；在同一局域网内使用 |

每个人拥有独立画布，不做多人共同编辑同一张画布。

## 5. 价值主张

### 对朋友

- **谁**：希望使用图片工作流、但不会制作 ComfyUI 工作流的朋友。
- **为什么**：需要生成和修改图片，并从多个结果中选出满意的版本。
- **现在怎么做**：在不同页面完成操作，手动下载、上传和整理图片。
- **我们怎么帮助**：提供现成工作流节点，在画布上通过连线传递文字和图片。
- **用了以后**：在一个界面连续创作，保留历史结果，并从选中的版本继续编辑。
- **替代方案**：分别使用现有工具处理，再通过文件夹管理结果；本产品将流程、参数和版本集中在各自的画布中。

价值主张：帮助不懂 ComfyUI 的朋友，通过简单节点和连线完成连续图片创作，并找回、比较和复用历史结果。

### 对维护者

- **谁**：统一提供工作流和执行资源的产品发起人。
- **为什么**：希望自己及朋友使用同一套工作流，同时保持各人的任务独立。
- **现在怎么做**：自行准备工作流，使用过程中仍需在不同页面流转图片和管理版本。
- **我们怎么帮助**：复用统一模板，开放指定参数，每个节点及任务保存自己的参数。
- **用了以后**：集中维护工作流，供多个用户分别使用，减少图片流转和整理步骤。
- **替代方案**：直接使用现有工作流界面，或把文件交给朋友配置；本产品提供统一准备、简单使用的入口。

价值主张：帮助维护者把自己准备的工作流交给朋友使用，同时保留模板稳定性和每个人独立的创作记录。

## 6. 解决方案

### 6.1 核心使用流程

1. 维护者启动局域网画布服务及本地 ComfyUI，配置 RunningHub 连接和工作流。
2. 用户打开网址，自行注册并登录，进入自己的画布。
3. 添加文字节点，或把电脑中的图片拖入画布。
4. 添加现成工作流节点，通过拖线连接输入，填写开放参数。
5. 单独运行一个工作流，或启动整条已连接流程。
6. 在结果节点中查看、切换和选择图片，再接入后续编辑。
7. 保存画布，下次登录恢复内容。

### 6.2 第一版功能与规则

| 编号 | 功能 | 关键规则 |
|---|---|---|
| F01 | 账号与独立内容 | 用户自行注册、登录；每个账号独立保存画布、参数、任务和历史结果 |
| F02 | 无限画布与手动连线 | 支持平移、缩放、摆放节点和手动连接文字、图片、工作流及结果节点 |
| F03 | 两类工作流 | 提供“文字生成图片”和“图片编辑”；工作流由维护者统一准备 |
| F04 | 两种执行来源 | 支持维护者电脑上的 ComfyUI 和 RunningHub；本地计算集中在维护者电脑；RunningHub 统一使用维护者账号 |
| F05 | 参数开放与隔离 | 维护者决定哪些参数开放；用户仅修改自己节点的参数；每次提交固定该任务的参数副本，不回写原始工作流，不影响其他任务 |
| F06 | 参数保存 | 每个节点的参数随所属画布保存并恢复 |
| F07 | 单步与整条运行 | 支持运行某个工作流，也支持启动整条连接流程 |
| F08 | 多次生成与历史结果 | 支持通过开放参数设置生成次数；同一工作流的图片收进同一个结果节点，默认显示最新图片，可切换历史；每次运行不另建图片节点 |
| F09 | 当前选图传递 | 下游编辑每次只使用当前选中的一张图片；查看并选中旧图后，可以从旧图继续编辑 |
| F10 | 两种选图方式 | 默认手动选图：生成后暂停，用户选图并点击“继续”；可切换自动方式：使用本次最新生成图片继续下游流程；模式随画布保存 |
| F11 | 本地任务排队 | 本地任务按提交顺序自动排队，用户能看到自己任务的排队状态 |
| F12 | 已有图片输入 | 支持把电脑中的图片拖入画布，并连到图片编辑工作流 |
| F13 | 数据持久化 | 数据库按用户保存画布、节点位置、连线、参数、选图状态和任务历史；重新登录后可恢复 |
| F14 | 图片流转 | 生成结果能够直接作为下游输入，用户无需手动下载再上传；支持在结果节点中切换比较图片 |

### 6.3 运行状态

需要让用户区分：等待运行、排队中、运行中、等待选图、已完成、失败。等待选图时应有明确的选图和继续入口。失败时显示对应步骤及可理解的原因。

### 6.4 约束与保存设计

- 第一版通过浏览器在同一局域网内使用。
- 本地工作流需要维护者电脑和 ComfyUI 服务运行；RunningHub 调用需要其服务可访问。
- 工作流模板、开放参数和运行连接由维护者统一配置。
- 用户使用相同模板时，运行参数、任务结果和保存内容按账号及节点区分。
- 图片可保存在维护者电脑的专用目录，数据库记录图片位置及归属。这是保存方案建议，尚未最终确认图片文件的存放方式。

### 6.5 假设与待确认问题

以下细节尚未讨论，不能视为已确认需求：

1. 注册字段、账号找回方式，以及工作流维护者如何进入管理界面。
2. 两类工作流各自开放哪些参数、默认值和允许范围；“生成次数”如何映射到具体工作流。
3. 比较图片采用节点内切换、并排展示，还是其他方式。
4. 多张结果如何分组；自动选图遇到同一批多张图片时，如何确定“最新”图片。
5. 本地与 RunningHub 的任务如何分别调度；等待选图是否释放执行资源；能否取消、重试，以及失败后从哪一步继续。
6. 数据库类型、图片存放位置、备份方式、画布自动保存时机和数量限制。
7. 模板更新后，旧画布如何继续运行，以及需要兼容哪些浏览器。

## 7. 发布范围

**第一版包含**：局域网浏览器访问、用户自行注册登录、独立无限画布、手动连线、文生图和图片编辑、两种工作流来源、开放参数及任务隔离、单步和整条运行、自动与手动选图、本地排队、已有图片输入、同节点历史结果和数据库保存恢复。

**本版明确不做**：朋友自行制作或导入工作流、多人共同编辑同一张画布、公网远程访问、桌面安装应用。

**后续范围**：其他工作流类型及更多功能待第一版验证后决定，目前不承诺。

**时间估计**：尚无开发资源和工作流接入测试结果，暂不承诺工期。建议依次完成“单人核心链路 → 保存与账号 → 多人参数隔离与排队 → RunningHub 接入 → 朋友试用验收”；两种来源全部通过验收后才算第一版完成。
